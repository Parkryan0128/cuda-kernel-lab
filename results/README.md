# Recorded measurements

| Directory | Purpose | Data |
|---|---|---|
| `tuning/` | Select one fixed default per operation | 11 processes, 22 case series, 660 samples |
| `release/` | Evaluate standard shapes, E2E, and transfers | 51 processes, 200 case series, 6,000 samples |
| `validation/` | Correctness, compiler evidence, and four sanitizer tools | 13 correctness functions; 9 boundary functions per sanitizer |

Each benchmark case has 30 raw samples. `samples.csv` is immutable recorded data. The accompanying `correctness.jsonl` records checks before and after measurement. `skipped.jsonl` records declared omissions (one standard G0 shape). `invocation.json` records the process command, exit, time, and pre/post GPU telemetry. A campaign `environment.json` records source/version provenance and measurement conditions.

`summary.json` files are generated by `scripts/summarize.py`. Their `raw_file` paths are relative to the campaign directory. p10/p90 describe batch-mean latency distributions; they are not individual-request tail percentiles. E2E uses one operation sequence per sample. The three `repeat*` groups are independent process launches, not three parts of one process.

Source snapshots were built and measured locally, then uploaded through the authenticated GitHub connector. That creates different commit metadata while preserving the exact Git source trees. [`provenance.json`](provenance.json) maps local measured commits to their published equivalents and records matching tree hashes. Raw metadata retains the original local build commit instead of being rewritten after publication.

After publication, CMake was updated to discover the CUDA 13 CCCL include directory for the host-compiled benchmark metadata code. This build-portability correction does not change kernels or timing logic. The recorded measurements still refer to the immutable snapshots above; a fresh build records its own commit and source digest.

The [reproduction guide](../docs/reproduction.md) defines the environment, scopes, and limitations. The [case studies](../docs/case-studies/reduction.md) interpret this evidence without treating profiler timing as unprofiled performance.
